# 0004 — Agent convergence is enforced in code, not requested in a prompt

Status: Accepted
Date: 2026-09-04

## Context

Running one query ten times to measure variance produced runs ranging from two tool calls to
more than fifty, and some that never finished at all. That looked like non-determinism. It
was not.

Replaying a failed run's recorded tool calls offline showed a precise sequence:

| call | window requested | total | validator returned |
| --- | --- | --- | --- |
| 2 | min 30:00, no maximum | 39:52 | **ok = true** |
| 3 | min 30:00, **max 30:00** | 39:52 | DURATION_OVER |
| 4–10 | min 30:00, max 30:00 | 17:35 – 29:19 | DURATION_UNDER ×7 |

The model had a correct, validated answer at call 2 and discarded it. It then narrowed the
window to demand a playlist of exactly 1,800,000 milliseconds — a target no subset of these
track durations can reach — and spent the remainder of its step budget failing at a problem
it had invented. Nobody asked for an exact duration; the user asked for "a 30 minute
playlist".

Each of those seven replies carried `"remedy": "add 363000 ms"`. The deterministic layer was
not merely detecting the error, it was handing over the exact correction. The model ignored
it seven times.

Three separate gaps allowed this:

- Nothing told the model it was finished when the validator returned `ok: true`.
- Nothing prevented it constructing an unsatisfiable constraint.
- `check_feasibility` had existed and been unit tested since the deterministic core was
  written, but was never exposed as a tool — so [rule 4](../../README.md), *feasibility is
  checked before generation*, had never actually been implemented.

The first attempted fix was an instruction in the system prompt: *"when validate_playlist
returns ok true, stop calling tools."* That instruction was present in the failing run. The
model ignored it.

## Decision

Constraint validity is enforced in code at the tool boundary, not requested in a prompt.

- `validate_playlist` rejects a duration window narrower than `MIN_DURATION_WINDOW_MS`
  before running any check, returning `invalid_constraints` together with a remedy naming
  the exact replacement bounds. The model cannot proceed with an impossible target because
  the tool will not evaluate one.
- `check_feasibility` is exposed as a tool, so a brief can be refused before any track is
  chosen.
- The agent runs under an explicit step ceiling (`MAX_STEPS`, passed as LangGraph's
  `recursion_limit`). This is not a fix. It converts "consumes the daily API quota" into
  "stops and reports that it did not converge", which is a failure mode that can be observed
  and counted.
- The system prompt still carries the corresponding instructions. They are steering, not
  guarantees, and are not relied upon.

## Evidence

Both samples are committed under `evals/variance/`, generated by
`scripts/measure_variance.py` against a pinned model:

| | before | after |
| --- | --- | --- |
| tool calls per run | 2 – 50+ | 3 – 5 |
| converged | not always | 10 / 10 |
| tokens per run | 6,887 – 24,907 | 7,152 – 12,956 |
| distinct track selections | varied | 2 |
| distinct final answers | varied | 9 |

The last two rows are the point. Fixing the defects collapsed the *trajectory* variance and
left the *content* variance untouched: ten runs still produced two different valid playlists
and nine different wordings. Before the fix those two kinds of variation were
indistinguishable, and the interesting one was buried under the avoidable one.

## Consequences

**Good.** A malformed constraint is now impossible rather than merely discouraged, which is
the same argument as [0001](0001-the-model-never-computes.md) applied one level up: where
something must be true, it belongs in code. Non-convergence became a countable outcome
instead of an unbounded cost. Rule 4 is implemented.

**Costly.** `MIN_DURATION_WINDOW_MS` is a judgement call — two minutes — and a genuine
request for a very tight window would be refused. That is preferred to the alternative,
because a tight window is far more often a model artefact than a user intention.

**Accepted risk.** The step ceiling can truncate a legitimately difficult brief that would
have converged in twenty-one steps. Runs that hit it are recorded as `did_not_converge`
rather than discarded, so the rate is measurable; if it becomes non-trivial the ceiling is
the thing to revisit, not the guard.

**What this record does not claim.** None of this removes non-determinism. Ten runs still
produce nine wordings. It removes the portion that was a defect, so that what remains can be
measured honestly — which is what the eval suite depends on.
